CloudVault — Secure Cloud Storage System

A modern, robust, and secure cloud storage web application designed with user isolation, resilient local file storage, and a modular architecture ready for Microsoft Azure Blob Storage.

User-Isolated Vaults

Every file belongs strictly to its authenticated owner. Server-side validation enforces file.user_id == current_user.id on every download, preview, and deletion operation.

Protected Storage Layer

Files are stored outside the public static directory with collision-resistant UUIDs, eliminating filename collisions, execution of untrusted scripts, and directory traversal attacks.

Azure Blob Ready

Built upon an abstract BaseStorageService interface. Switching from local disk storage to Microsoft Azure Blob Storage requires zero modifications to the UI or route handlers.

Microsoft Azure Blob Storage Integration Plan

Architectural design for seamless Phase 2 Cloud deployment

1

Storage Service Interface

Both LocalStorageService and AzureBlobStorageService inherit from BaseStorageService, implementing identical signatures for save_file(), get_file_path(), delete_file(), and file_exists().

2

Azure Blob Storage SDK

In Phase 2, installing azure-storage-blob will activate the BlobServiceClient to stream bytes directly to private Azure Blob Containers with access tiering (Hot/Cool/Archive).

3

Shared Access Signatures (SAS)

Downloads can utilize short-lived time-bounded Shared Access Signature (SAS) tokens generated securely on the backend, offloading bandwidth from Flask to Azure CDN.

4

Environment-Driven Switch

Changing STORAGE_TYPE=azure in .env with credentials allows immediate cloud deployment to Azure App Service without altering a single line of frontend code.

services/storage_service.py — Adapter Swapping Flow 
# Current development mode (Active):
storage = LocalStorageService(upload_folder='storage/uploads')

# Planned Microsoft Azure deployment (Phase 2):
storage = AzureBlobStorageService(
    connection_string=os.environ['AZURE_STORAGE_CONNECTION_STRING'],
    container_name=os.environ.get('AZURE_CONTAINER_NAME', 'cloudvault-files')
)

# Route handlers remain completely identical:
storage.save_file(user_id=current_user.id, file_stream=file.stream, stored_filename=name)
storage.delete_file(user_id=current_user.id, stored_filename=name)
